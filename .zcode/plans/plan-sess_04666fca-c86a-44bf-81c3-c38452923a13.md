## 目标

1. **完善通知渠道**：speak（小爱音箱播报）渠道支持**多选音箱设备**，消除"未指定有效的小爱设备ID"错误
2. **API 密钥绑定通知渠道（多选）**：密钥可勾选 0~N 个通知渠道；用该密钥调 `/notify/send` 且不指定渠道时，自动向**所有绑定的启用渠道**推送

## 一、通知渠道：speak 类型多选设备

**后端**（小改，链路已通）：
- `notification_service._send_speak`（:664）：支持 `config.device_ids`（列表）优先，兼容旧 `device_id` 单值；`SpeakRequest.device_id` 本就支持数组，`speak_service.speak_text` 支持多设备并发播报，无需改动
- `schemas/notification_channel.py`：speak 类型 config 增加 `/config` 提示（device_ids 为音箱设备ID数组）

**前端**：
- `api/channels.js`：speak 的 `fields` 增加 `{key: 'device_ids', type: 'devices'}`（多选设备）
- `ChannelsView.vue`：表单渲染新字段类型 `devices`——挂载时调 `api/devices.js` 现成的 `listDevices()`（自带三级回退，已归一化 `device_id/name/online`），用 checkbox 列表（`.switch`/`.checkbox` 现成样式）多选；编辑回填 device_ids 勾选态；卡片 `configSummary` 显示所选设备名
- 修复"编辑 speak 渠道回显"：device_ids 非敏感字段，脱敏函数不会碰它，回填天然可用

## 二、API 密钥绑定通知渠道（多选）

**数据模型**：
- `models/api_key.py`：新增 `channel_ids` JSON 列（存 `[int]`）
- `database.py MIGRATIONS`：追加 `{"table": "api_keys", "column": "channel_ids", "ddl": "TEXT"}`（幂等补列）

**后端**：
- `schemas/api_key.py`：Create/Update/Response 增加 `channel_ids: Optional[List[int]]`
- `services/api_key_service.py`：create/update 时校验渠道**归属**（channel.user_id == key.user_id）与存在性，整体替换语义
- `routers/notifications.py`：`get_notify_caller` 改为返回 `(user, api_key_obj|None)`（JWT 时 obj 为 None），把 key 对象传给业务层
- `services/notification_service.py`：`send_notification` 增加参数 `bound_channel_ids`——请求未带 `channel_id`/`channel_type` 且来自 API Key 时，解析绑定的启用渠道**逐个发送**（复用现有单渠道路径），`NotificationSendResponse` 增加 `results: [{channel_id, channel_name, success, log_id, message}]`；请求显式指定渠道时优先用请求的（覆盖绑定）
- 语义矩阵：API Key + 无渠道参数 → 发到全部绑定渠道；API Key + 显式 channel_id → 用显式的；JWT → 行为不变（必须显式指定）

**前端**：
- `ApiKeysView.vue`：创建/编辑模态加"绑定通知渠道"多选区（拉 `listChannels()` 渲染 checkbox 组，展示渠道名+类型徽章）；密钥卡片加已绑定渠道 chips
- `api/apiKeys.js`：payload 带 `channel_ids`

**文档**：`DocsView.vue` 的 /notify/send 说明补充新语义（绑定渠道免传参）
